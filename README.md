# Navi

מסלולי טיול בתלת־ממד, בישראל ובעולם, עם מדריכה קולית בעברית. אפליקציית Next.js
שרצה ב-Vercel (`navi-v1.vercel.app`), עם עטיפת אנדרואיד ב-`android-app/`.

## הגדרה — איפה שמים את המפתחות

**המפתחות לא נשמרים ב-GitHub, לעולם.** `.gitignore` חוסם כל קובץ `.env*`
(מלבד `.env.local.example`, שהוא תבנית עם ערכים ריקים). מפתח שנדחף ל-repo
ציבורי נסרק ונגנב תוך דקות, ולכן יש בדיוק שני מקומות נכונים:

### 1. פיתוח מקומי — קובץ `.env.local`

בשורש הפרויקט, ליד `package.json`:

```bash
cp .env.local.example .env.local
```

פתח את `.env.local` בעורך ומלא את הערכים. הקובץ נשאר רק על המחשב שלך.
אחרי כל שינוי בו צריך להפעיל מחדש את `npm run dev` — Next.js קורא את משתני
הסביבה פעם אחת בעלייה.

### 2. הפרודקשן ב-Vercel — לא קובץ, אלא ממשק

Vercel לא רואה את `.env.local` שלך. שם המשתנים מוגדרים בדשבורד:

**Vercel Dashboard → הפרויקט → Settings → Environment Variables**

לכל משתנה: Key, Value, ולסמן את שלוש הסביבות (Production / Preview /
Development). משתנה חדש נכנס לתוקף רק ב-deploy הבא — אחרי ההוספה צריך
**Deployments → הפריסה האחרונה → ⋯ → Redeploy**.

## המדריכה הקולית

נקודה הופכת לנקודת מדריכה רק כשידוע עליה משהו ספציפי: ערך בוויקיפדיה העברית
*על הנקודה עצמה*, או תיאור של ממש בתגיות OpenStreetMap שלה (`src/lib/grounding.ts`).
נקודה שאין מה לומר עליה לא מופיעה בכלל. הנקודות מתגלות דרך Overpass ונשמרות
בטבלה `trail_pois`, כי Overpass נכשל לעתים קרובות ובאקראי.

הקריינות נכתבת על ידי מודל שפה רק מתוך המקורות, ונשמרת בטבלה `poi_narration`;
האודיו נשמר ב-bucket `narrations`. משלמים פעם אחת לכל נקודה, וכל המשתמשים
שומעים את אותה קריינות. הספקים נוסים לפי הסדר: הבחירה בהגדרות, `AI_PROVIDER`,
ואחר כך Gemini החינמי → OpenAI → Gemini בתשלום → Claude. ספק שנכשל מושהה ל-10 דקות.

### בחירת קול — בלי deploy

`ELEVENLABS_VOICE_ID` הוא רק ברירת המחדל של השרת. כדי לנסות קולות, פתח
באפליקציה **הגדרות → מתקדם → הקול של המדריכה** (למנהל האתר בלבד, ראה "כלי המנהל"): בחר מהרשימה, כוונן את המחוונים,
ולחץ "השמע משפט לדוגמה".

**הרשאות המפתח.** מפתחות ה-API של ElevenLabs מוגבלים בהרשאות: מפתח יכול להיות
מורשה לייצר דיבור ועדיין חסום מלקרוא את רשימת הקולות. במקרה כזה הקריינות
עובדת אבל הרשימה בהגדרות חוזרת ריקה עם 401 `missing_permissions`. התיקון הוא
ElevenLabs → Profile → API Keys → עריכת המפתח → סימון ההרשאה החסרה (`voices_read`).
לא צריך מפתח חדש ולא צריך Redeploy.

**חשוב — לא כל קול שמתנגן באתר עובד ב-API.** בתוכנית החינמית קולות מה-Voice
Library חסומים ל-API ומחזירים 402 `paid_plan_required`, גם כשנשארו קרדיטים.
זו מגבלה על *סוג* הקול ולא על הכמות. לכן הרשימה בהגדרות נטענת מהחשבון עצמו
דרך `/api/tour-guide/voices` — היא בדיוק מה שהחשבון רשאי להשמיע ב-API, במקום
רשימה מנוחשת בקוד. הבחירה נשמרת במכשיר בלבד ונשלחת עם כל בקשה, כך
שאפשר להשוות קולות בתוך שניות. כפתור האיפוס מחזיר להגדרת השרת.

מזהה הקול וכל ההגדרות הם חלק ממפתח ה-cache של האודיו, ולכן מעבר בין קולות
לא דורס כלום — וחזרה לקול שכבר השתמשת בו היא בחינם.

בראש אותו פרק מוצג **מאיזה ספק הקול מגיע בפועל**. זה חשוב: ElevenLabs נבחר רק
אם *גם* `ELEVENLABS_API_KEY` *וגם* `ELEVENLABS_VOICE_ID` מוגדרים בשרת; אם אחד
מהם חסר, הקוד נופל בשקט ל-OpenAI או ל-Gemini. מבחוץ זה נראה זהה — המחוונים
פשוט מפסיקים להשפיע. החיווי אומר את זה במפורש.

### ניקוד לפני ההקראה

עברית נכתבת בלי ניקוד, ומודל הקראה מנחש את התנועות. לפעמים הניחוש מחליף מילה
שלמה: "מהר מירון" (מ + הר מירון) נקרא כ-"מַהֵר", כלומר *fast*. הניקוד מתבצע
רגע לפני שהטקסט נשלח ל-TTS, ולא בזמן כתיבת הקריינות — כך הטקסט השמור נשאר
עברית קריאה, וכל שיפור כאן חל בלי לייצר מחדש אף קריינות.

יש שני מנקדים, ו-`NIQQUD_PROVIDER` בוחר ביניהם:

**`dicta` (ברירת המחדל).** [Nakdan](https://nakdan.dicta.org.il/) של DICTA —
מודל ניקוד לעברית מודרנית. מנקד את כל המשפט, כולל שמות פרטיים ואוצר מילים
רגיל: "חקלאות", "שלווה" ושמות מסלולים שאף טבלה לא תכיל. השירות ציבורי, חינמי
ולא דורש מפתח. כל קריאה היא לשירות של גורם אחר, ולכן היא אופציונלית לגמרי:
פסק זמן של 6 שניות, ניסיון אחד, ונפילה חזרה לטבלה בכל כשל.

> **בדיקת בטיחות.** התשובה של Nakdan מתקבלת רק אם הסרת הניקוד ממנה מחזירה בדיוק
> את הטקסט שנשלח. מותר לה להוסיף סימני ניקוד ותו לא. אם האותיות חזרו שונות —
> מכל סיבה — התוצאה נפסלת והטבלה עונה במקומה. זה מה שמונע משירות חיצוני לשים
> מילים בפי המדריכה.

**`lexicon`.** `src/lib/niqqud.ts` — טבלה של אוצר המילים הגיאוגרפי (נַחַל, עֵין,
חֻרְבַּת, מַעֲלֵה…), בלי רשת ובלי עלות. היא מכסה גם תחיליות של אות אחת ששתי
האפשרויות שלהן נקבעות מהמילה עצמה: מ (מֵהַר, מִנַּחַל), ה מיודעת לפני אות
שאינה גרונית (הַנַּחַל), ו-ו לפניהן (וּמֵהַר). ב, כ ו-ל **לא** נכללות בכוונה:
"בנחל" הוא או בְּנַחַל או בַּנַּחַל תלוי אם ה"א הידיעה נבלעה, והטקסט הלא-מנוקד
לא אומר מה מהם. היא גם לא נוגעת בשם הפרטי שאחרי (כזיב, צאלים, עתרי).

`NIQQUD_VERSION` וזהות המנקד הם חלק מחתימת הקול, ולכן שינוי כאן מייצר אודיו
חדש במקום להגיש את ההקראה הישנה מה-cache.

**בדיקה.** בהגדרות → מתקדם → **בדיקת ניקוד** אפשר להזין כל משפט ולראות מה כל אחד משני
המנקדים עושה לו, בלי לייצר קול ובלי לצרוך קרדיטים. זו גם הדרך היחידה לוודא
ש*השרת* מצליח להגיע ל-Nakdan: התשובה כוללת את הכתובת שאליה פנה ואת השגיאה
המדויקת אם נכשל. אם Nakdan חסום מהפרודקשן, הקריינות תמשיך לעבוד — היא פשוט
תישמע כמו הטבלה בלבד. אפשר גם לכבות ניקוד לגמרי מאותו מסך.

### איזה קול דיבר בפועל

`ELEVENLABS_VOICE_ID` נשמר ב-cache יחד עם האודיו, ולכן החלפת קול לא דורסת
הקלטות קודמות — וזה בדיוק מה שמקשה לדעת מה נשמע כרגע. שלוש שכבות עונות על זה:

- **בזמן ההשמעה** מוצג מתחת לטקסט של המדריכה שם הקול והמזהה שהפיקו את הקטע
  הזה — לא מה שמוגדר בשרת עכשיו, אלא מה ששימש בפועל. קטע שהושמע מהמכשיר מסומן
  "מהמכשיר".
- **בהגדרות** החיווי הירוק מדווח על הקול שהשרת יבחר עבור ההעדפות של המכשיר
  הזה, כולל המנקד הפעיל.
- **משפט הדוגמה** מחזיר גם את הטקסט המנוקד שנשלח בפועל לקול.

ההורדה לאופליין נשמרת לפי (נקודה + חתימת קול). קריינות שהורדה בקול ישן לא
תושמע יותר: הנקודה תסומן שוב "להורדה", וההורדה הבאה תחליף אותה ותמחק את
העותקים בקולות שכבר לא בשימוש. עד לגרסה הזו העותק במכשיר נבדק לפי הנקודה בלבד,
כך שמסלול שהורד פעם המשיך להשמיע את הקול הישן לנצח — וזה נראה בדיוק כמו
"שינוי הקול לא עבד".

## מפה בשטח בלי קליטה

"נקודות" → **"הורד מסלול לשטח"** שומר במכשיר את הקריינות **ואת המפה** לאורך המסלול:
אריחי הלוויין והרחובות של Mapbox בזום 5–16 (כמטר לפיקסל בשטח), הטריין לתלת-ממד, הסגנון
והגופנים. מסלול של 14 ק"מ ≈ 20 MB. אחרי זה המסלול מופיע במסך הבית תחת "שמורים לשטח"
ונפתח גם בלי רשת — עם המפה, הקו, הנקודות, הקריינות שהורדה ומצב שטח עם GPS.

**איך זה עובד.** ה-Service Worker (`public/sw.js`) שומר כל מה שהמפה מביאה מ-Mapbox
במטמון `navi-map-v1`, לפי ה-path של הבקשה. ההורדה (`src/lib/offlineMap.ts`) מחשבת
את אריחי הפרוזדור סביב המסלול (`src/lib/tileCorridor.ts`), מביאה אותם ישירות
מ-api.mapbox.com לתוך אותו מטמון, ורושמת חבילה ב-IndexedDB. בלי קליטה המפה מקבלת
את האריחים מהמטמון ולא מרגישה בהבדל.

**30 יום.** תנאי המוצר של Mapbox (§2.8.1) מרשים לשמור תוכן על מכשיר הקצה עד שלושים
יום, בתנאי שהמכשיר עצמו הביא אותו מה-API. הקוד אוכף את זה: כל רשומה נושאת חותמת
זמן, ומה שעבר 30 יום נמחק ולא מוגש. שורת התוקף מתחת לכפתור אומרת עד מתי החבילה
טובה; לפני היציאה לשטח — "רענן הורדה" משלים רק את מה שחסר. הרקע המלא, החלופות
שנבדקו ונוסח לפנייה ל-Mapbox: `docs/plan-offline-maps.md`.

**באנדרואיד** (המכשיר שהאפליקציה נבדקת עליו — Pixel) הכל עובד גם מ-Chrome רגיל;
"הוסף למסך הבית" נותן אייקון ומסך מלא, וההורדה מבקשת אחסון קבוע (`storage.persist`)
כדי שהדפדפן לא יפנה אותו בלחץ מקום. **באייפון**, למי שמשתמש: חובה להוסיף את Navi למסך
הבית ולפתוח משם — Safari מוחק אחסון של אתר רגיל אחרי שבעה ימים בלי שימוש.

**בדיקה בבית.** הגדרות → מתקדם → "בדיקה בלי קליטה" → "דמה אובדן קליטה" → רענון. המפה, הקריינות
והמסלולים מגיעים רק ממה שנשמר. הבדיקה עובדת על build ייצור (`npm run build` ואז
`npx next start`); ב-`next dev` הדף לא עובר hydration בלי רשת — עניין של Turbopack
בפיתוח, לא של האפליקציה.

## "על המסלול"

כפתור בכרטיס המסלול שפותח תיאור בעברית: סיכום, נתונים, וסעיפים (גישה, מים,
עונה וכו') עם הפניה למקורות. המקורות מדורגים: אתר רשמי של המסלול, נאקב (במסלולים
בישראל — המספר בסוף שם קובץ ה-GPX הוא המזהה בנאקב), ויקיפדיה, ורק אם אין
מספיק — חיפוש ברשת ב-Tavily. התיאור נכתב פעם אחת לכל מסלול, נשמר בטבלה
`trail_info` לכולם ומתחדש אחרי 90 יום.

## תמונות מהמסלול

שורה "תמונות מהמסלול" בכרטיס המסלול (בישראל ובעולם; לא בנסיעה). בפתיחה הראשונה
של מסלול השרת בוחר את התמונות — עד חצי דקה — ושומר את הבחירה בטבלה
`trail_photos` לכולם; מתחדש אחרי 90 יום.

- **המקורות, כולם חינמיים:** ויקישיתוף (Wikimedia Commons) — תמונות עם מקום הצילום,
  כולל העברות מ-Panoramio, Flickr, Geograph, פיקיויקי והתמונות שמטיילים מעלים
  מ-Israel Hiking Map. Panoramax (תמונות רחוב פתוחות) רק לקטעים שאין להם תמונה
  בוויקישיתוף — באירופה בעיקר, בישראל כמעט אין. במסלול עולם — גם התמונה של המסלול
  עצמו מ-OpenStreetMap / Wikidata, ראשונה ("תמונת המסלול").
- **שנבדקו ונדחו:** Mapillary — מכסה כבישים, לא שבילים (נבדק במכתש רמון, בנחל עמוד
  ובדולומיטים). Flickr — מפתח API רק לחשבון Pro בתשלום. תמונות Google — בתשלום
  ואסור לשמור, ולכן רק כפתור "עוד תמונות בגוגל". Unsplash / Pexels — בלי מיקום.
- **הפיזור לאורך המסלול** (`src/lib/trailPhotos/select.ts`): המסלול מחולק לקטעים
  שווים — אחד לכל כ-1.5 ק״מ, בין 4 ל-12 — ומכל קטע לכל היותר תמונה אחת. תמונות
  מאותו צילום (אותו צלם, אותו מקום, בתוך חצי שעה; קבצים בשם דומה; אותו רצף
  ב-Panoramax) נחשבות אחת, וכך גם תמונות ש-Gemini אומר שמראות אותו נוף. קטע בלי
  תמונה נשאר ריק — לא לוקחים במקומו תמונה שנייה מקטע עשיר. אף צלם לא יותר
  משליש, כשיש תמונה של צלם אחר לאותו קטע.
- **מה נחשב תמונה של המסלול:** עד 700 מ׳ מהשביל בוויקישיתוף (המצלמה עומדת
  לפעמים בתצפית מעליו), עד 50 מ׳ ב-Panoramax. נפסלים לפי השם והקטגוריות: מפות,
  שלטים, מסמכים, צילומי פנים, ותקריבים של צמח או בעל חיים (שם מדעי). Gemini
  החינמי (`GEMINI_FREE_API_KEY` בלבד) מסתכל על שתי המועמדות הטובות של כל קטע ופוסל
  את מה שאינו נוף. בלי המפתח, או כשהמכסה נגמרה, הבחירה נעשית רק לפי השם, המקום
  והקטגוריות, ונבחרת שוב אחרי שבוע.
- **כמה יש:** בבדיקה על מסלולים אמיתיים — בישראל 3/6 עד 8/12 קטעים עם תמונה;
  בעולם, מסלולים מוכרים (לאוגווגור, טרולטונגה) מכוסים היטב, ומסלול מקומי רגיל
  (צרפת, פורטוגל, אלבניה) לרוב מקבל 0–2 תמונות — ואז בעיקר כפתור הגוגל.
- **קרדיט:** בכל תמונה במסך המלא — הצלם, הרישיון וקישור לדף התמונה במקור, כפי
  שרישיונות CC דורשים. התמונות לא נשמרות אצלנו; מוצגות ישירות מהמקור.
- **בדיקה:** `node scripts/checkPhotos.mjs` (הכללים), ועם `--live` גם על
  מסלולים אמיתיים. אחרי שינוי כלל — מעלים את `PHOTOS_VERSION` ב-`cache.ts`.

## תחזית ליום הטיול

בכרטיס המסלול → "נתונים" → "מזג אוויר ליום הטיול" (השורה מראה את היום, הטמפרטורה ונקודת צבע; לחיצה פותחת הכל): תחזית לפי יום ושעת יציאה, בבלוקים לאורך היום, עם כמות
מים מומלצת (טווח, כולל רזרבה בקיץ), ביגוד ואזהרות. החישובים כולם בכללים קבועים
(`src/lib/hikeAdvice.ts`). אפשר להפעיל גם הסבר במילים שמודל שפה כותב
(`/api/trip-advice`): הוא כבוי כברירת מחדל, משתמש רק ב-`GEMINI_FREE_API_KEY`
ולעולם לא במפתח בתשלום, ואסור לו לשנות אף מספר.

## שאלו את Navi

כפתור עגול כחול בתחתית המסך (בטלפון מימין, במחשב משמאל) פותח צ׳אט. בטלפון, במסך הבית,
החלונית המקופלת של המסלולים (או של הנסיעה) צרה יותר והכפתור עומד לידה, באמצע הגובה שלה
(`src/hooks/useHelpChatBeside.ts`); כשהחלונית נפתחת או כשמסלול פתוח הוא חוזר לפינה. הצ׳אט
שעונה על שאלות על השימוש באפליקציה — "איך מורידים מסלול לשטח?", "איפה ההקלטות
שלי?" — במשפט עד שלושה. מתחת לתשובה יכולים להופיע עד שני כפתורים שפותחים ישר את
מה שהיא מדברת עליו (רשימת המסלולים, הנקודות, הקלטה, סיור וירטואלי, ההדרכה של
המסך…), ו"הראה לי איפה" — שמסמן על המסך את הכפתור שהתשובה מדברת עליו, בטבעת
כתומה עם השם שלו. "הסתר הכל" מעלים גם את הצ׳אט. "שיחה חדשה" מתחיל מחדש, ו"היסטוריה"
פותחת אחת מ-5 השיחות הקודמות; השיחות נשמרות רק במכשיר (`navi:helpChat.v1`), ומי
שחוזר אחרי 6 שעות מתחיל שיחה חדשה. בלי קליטה הצ׳אט לא עובד ומפנה ל"מדריכים ומידע
נוסף" בהגדרות.

- **מה הוא יודע:** רק את ההסברים של "מדריכים ומידע נוסף"
  (`src/components/help/features.ts`), את המילים של ההדרכות (`tours.tsx`) ואת
  **מפת המסך** (`src/lib/helpChat/places.ts`): לכל כפתור — איפה הוא, איך האייקון
  שלו נראה ומתי הוא מופיע (כפתורי המסלול רק כשמסלול פתוח). עם כל שאלה נשלח גם מה יש
  על המסך עכשיו: מסלול פתוח, נסיעה, הקלטה, והאם שמות הכפתורים מוסתרים. לא המיקום ולא
  פרטי המסלול. **יכולת חדשה צריכה שורה ב-`features.ts`**, וכפתור חדש או שזז — שורה
  ב-`places.ts` ו-`data-tour` על הכפתור, אחרת הצ׳אט לא יודע עליהם.
- **כפתורים:** רק מתוך הרשימה הקבועה ב-`src/lib/helpChat/actions.ts`; כל אחד מחובר
  ב-`page.tsx` (`runHelpAction`) לאותה פעולה שהכפתור המקורי עושה.
- **מודל ומכסה:** `GEMINI_FREE_API_KEY` בלבד (`GEMINI_HELP_MODEL`, ברירת מחדל
  `gemini-3.5-flash-lite`), אף פעם לא מפתח בתשלום. 30 שאלות ביום לכל מכשיר, 80 לכל
  כתובת IP ו-6 בדקה (Upstash). מעבר לזה, או כשהמכסה של Google נגמרת, הצ׳אט אומר זאת.
- **יומן:** כל שאלה נשמרת ב-`help_chat_log`, בלי מי ששאל, למנהל (ראו "כלי המנהל").

## מתי כדאי ללכת

בכרטיס המסלול, שורה "מתי כדאי ללכת": 12 החודשים בצבעים, ובשורה הסגורה החודשים
המומלצים ("עונה מומלצת: מרץ–מאי, אוק׳–נוב׳"). לחיצה על חודש מראה למה הוא דורג כך.
לא "עונות" — אביב בערבה ואביב בחרמון הם מזג אוויר אחר — אלא כל חודש לחוד:

- **עונה מומלצת / אפשרי בהיערכות / לא מומלץ** — החודש מקבל את הגרוע מבין ארבעה:
  עומס חום בנקודה הנמוכה (אותו מדד של השירות המטאורולוגי שהתחזית משתמשת בו),
  קור ושלג בנקודה הגבוהה, כמות הגשם, ושעות האור מול אורך ההליכה. במסלול של יותר
  מ-5 שעות החום נספר חמור יותר, ובפחות משעתיים — פחות.
- **גשם לפי עונה, לא לפי מעלות**: בחצי החם של השנה (במקום עצמו) גשם הוא לרוב
  ממטרים שעוברים, ובחצי הקר הוא מגיע בחזיתות — ימים שלמים, בוץ וסלע רטוב — גם
  כשהחורף מתון. בחצי הקר "אפשרי בהיערכות" כבר מ-90 מ״מ בחודש ו"לא מומלץ" מ-200;
  בחצי החם מ-150 ומ-300 (מונסון); בחודשי המעבר הסף משתנה בהדרגה. באזורים טרופיים,
  שבהם אין עונה קרה, כל החודשים נחשבים חמים. (הגרסה הראשונה הלכה לפי טמפרטורה,
  ובגללה ינואר הגשום בכרתים ובחוף הליקי יצא "עונה מומלצת".)
- **ערוץ או קניון**: מסלול ששמו אומר gorge/canyon/φαράγγι/Schlucht וכו' (לא "נחל")
  מקבל בחודשים הגשומים של החצי הקר סף מחמיר — מ-40 מ״מ "אפשרי", ומ-100 "לא מומלץ",
  בגלל שיטפונות וסלעים חלקים. Kritsa Gorge בכרתים, למשל: אפריל–יוני וספטמבר–אוקטובר
  מומלצים, דצמבר–פברואר לא.
- **מקור הנתונים**: הממוצעים החודשיים של TerraClimate לשנים 1991–2020 (נחלת
  הכלל), בגריד של 0.25° עם הגובה הממוצע של כל תא, **מותאמים לעשור האחרון**:
  ממוצע 30 שנה מתאר את האקלים של סביב 2005, ומאז התחמם — 2016–2025 חמות מהממוצע
  בכ-0.7° בישראל ובכ-1.25° באלפים. לכן הטמפרטורות, הלחות והשלג מוזזים לפי ההפרש
  בין העשור הזה לממוצע (מתוך הסדרה החודשית של TerraClimate עצמו), מוחלק על פני
  אזורים וחודשים סמוכים כדי שחורף חריג אחד לא ייהפך לכלל. הגשם נשאר לפי 30 השנים —
  עשור קצר מדי בשביל גשם, ואין בו שינוי ברור. כשיתווספו שנים לסדרה, אפשר להזיז את
  העשור ב-`RECENT_FROM`/`RECENT_TO` בסקריפט ולבנות מחדש. הטמפרטורה מתוקנת לגובה האמיתי
  של המסלול (6.5° לכל קילומטר). הגריד הוא קובץ של כ-6.5MB שנמצא בקוד
  (`src/data/climate-grid.bin.gz`) ונבנה פעם אחת ב-`scripts/buildClimateGrid.mjs`
  — אין קריאה לשום שירות חיצוני ואין עלות.
- **בדיקה**: `node scripts/checkClimate.mjs` מריץ את הכללים על מקומות ידועים (ים
  המלח, ירושלים, מירון, החרמון, אילת, האלפים, איסלנד, פטגוניה, קרלה) ועל מסלולים
  פופולריים שהעונה שלהם מפורסמת (Kritsa ו-Samaria בכרתים, הדרך הליקית, צ׳ינקווה
  טרה), ונכשל אם חודש יצא לא הגיוני. כל שינוי בספים נבדק מולו.
- **מסלול של כמה ימים** (מעל 25 ק״מ): נקודות לאורכו מדורגות כל אחת כיום הליכה
  מלא, והחודש מקבל את מה שיצא ברוב הנקודות — אחרת קצה מדברי וקצה הררי היו הופכים
  כל חודש ל"לא מומלץ". שביל ישראל, למשל, יוצא מומלץ בנובמבר–אפריל. זה רק כשהנקודות
  רחוקות זו מזו יותר מ-15 ק״מ (`crossesClimates`); מסלול ארוך שנשאר באזור אחד —
  לולאה סביב כפר, סובב רכס — לא עובר בין אקלימים, ומדורג כמו מסלול יום: חום בנקודה
  הנמוכה וקור ושלג בגבוהה. אחרת הנקודות בעמק "גוברות" על הרכס: הלולאה של 26 ק״מ מעל
  Rocchetta Nervina בליגוריה (215–1436 מ׳) יצאה "עונה מומלצת" בינואר, כשבחלק הגבוה
  כ-0° בלילה וכ-6° ביום.
- **גשם במילים**: ליד כמות הגשם החודשית מופיע תיאור — כמעט יבש (פחות מ-10 מ״מ),
  מעט גשם (עד 40), גשם מתון (עד 100), גשום (עד 200), גשום מאוד (מעל 200) — עם
  הסבר קצר כמה פעמים יורד גשם בחודש כזה (`rainWords` ב-`src/lib/climate.ts`).
- התשובה נשמרת במכשיר ועובדת גם בלי קליטה. זה ממוצע רב-שנתי, לא תחזית.

## מסלולים בעולם

בחלונית "מסלולים לפי מדינות, עונות ומאפיינים נוספים" (עד 2026-10: "חפש/העלה מסלולים") יש לשונית **"מסלולים בעולם"** (עד 2026-10: "בעולם לפי
חודש"), עם שלוש דרכים:

- **לפי חודש** — בוחרים חודש ורואים מיד את כל המדינות שיש בהן אזורים ב"עונה
  מומלצת" באותו חודש, ואיזה אחוז מהשטח שלהן. זה מחושב מגריד האקלים בלבד (כל תא
  מדורג כמו יום הליכה של 4 שעות בגובה שלו), בלי לבנות רשימות מראש. ליד מדינה
  שכבר נפתחה פעם מופיע גם כמה מסלולים בה מומלצים בחודש הזה.
- **לפי מדינה** — בוחרים מדינה, ואז חודש ודרגה.
- **לפי דירוג** — כל המסלולים שיש עליהם נתוני Komoot, בלי לבחור מדינה קודם (ראו
  "דירוג מסלולים בעולם" בסעיף "מה אומרים מטיילים").

בשתי הדרכים הראשונות יש מתחת לחיפוש שורת **יבשות** (כל העולם, אירופה, המזרח התיכון, אסיה,
אפריקה, צפון ומרכז אמריקה, דרום אמריקה, אוקיאניה) שמצמצמת את רשימת המדינות. המזרח
התיכון הוא קבוצה בפני עצמה, לא חלק מאסיה: ישראל ושכנותיה, המפרץ, איראן, מצרים
וטורקיה. מרכז אמריקה והאיים הקריביים נמצאים תחת צפון אמריקה. רוסיה וארצות הקווקז
מופיעות גם באירופה וגם באסיה, טורקיה גם באירופה וגם במזרח התיכון, ומצרים גם במזרח
התיכון וגם באפריקה. השיוך נמצא ב-`src/lib/continents.ts`.

בחירת מדינה מציגה קודם את **האזורים** שלה — מחוז, קנטון או מדינה (state), עם
כיוון בתוך המדינה (צפון, דרום-מערב, מרכז…) וכמה מסלולים בכל אחד מתאימים לחודש
ולדרגה שנבחרו — ואחרי בחירת אזור את המסלולים שבו, מסוננים לפי החודש והדרגה.
מסלול ארוך מופיע בכל אזור שהוא עובר בו. לחיצה על מסלול פותחת את הכרטיס שלו, כמו
בחיפוש. האזורים מ-Natural Earth (נחלת הכלל), עם שמות בעברית; במדינה שיש בה יותר
מ-30 (מחוזות איטליה, מחלקות צרפת, בריטניה) הם מקובצים לאזורים הגדולים יותר, שמוצגים
בשם המקורי. הקובץ `src/data/regions.json.gz` נבנה פעם אחת ב-`scripts/buildRegions.mjs`. Waymarked מחזיר לכל
היותר 100 מסלולים לאזור, החשובים קודם, ולכן המדינה מחולקת לעד 12 ריבועים: במדינה
קטנה מגיעים גם למסלולים מקומיים, ובמדינה גדולה בעיקר לאזוריים ולארציים. הריבועים
מכסים רק את המדינה עצמה, בלי השטחים שלה מעבר לים (איי פוקלנד של בריטניה, סבאלברד של
נורווגיה, גרינלנד של דנמרק, גיאנה הצרפתית); איים שהם חלק מהמדינה — האיים הקנריים,
האזורים, הוואי, קורסיקה — נשארים. עד 2026-10 הם נכללו, והריבועים יצאו ענקיים: הרשימה
של בריטניה יצאה עם 2 מסלולים ושל צרפת עם 115. לכל מסלול
נלקחים קטע בתוך המדינה, גבהים מ-Open-Meteo, ואותם כללי דירוג של הכרטיס.
**שבילים בינלאומיים** (E4, E6, Sultans Trail) לא נכנסים לרשימה של מדינה: הכרטיס
וה"טען" שלהם הם השביל כולו, אלפי קילומטרים, ו"טען" היה טוען את הקטע הארוך ביותר —
ביוון, את ה-E4 בספרד. החלקים שלהם בתוך המדינה ממופים כמסלולים בפני עצמם ("E4 – part
Greece, Central") ונשארים.

**שבילים מקומיים שהריבועים לא מגיעים אליהם.** במדינה גדולה ריבוע הוא עשרות
קילומטרים, ו-Waymarked עונה עליו ב-100 השבילים הארציים והאזוריים שבו — בלי אף שביל
מקומי (נבדק סביב מונסראט: בריבוע של 2 ק"מ 24 שבילים, ביניהם המקומי "Del Monestir a Sant
Jeroni"; בריבוע של 50 ק"מ 100 שבילים, אף לא מקומי אחד). יותר ריבועים לא פותרים את זה —
צריך ריבועים של קילומטרים בודדים, אלפים למדינה. במקום זה, השבילים המקומיים שחשובים
באמת נמצאים דרך "מה אומרים מטיילים": מתחת לכל מסלול פופולרי של Komoot נבדק מה עובר
שם בדיוק, והשביל שהמסלול הולך עליו נוסף לרשימה (ראו שם). הוא נשמר בטבלה `trail_crowd`,
ולכן גם בנייה מחדש של הרשימה מחזירה אותו — עם השם של המסלול ב-Komoot, אם ב-OSM אין
לו שם.

בניית מדינה בפעם הראשונה לוקחת 5–30 שניות. אחר כך היא נשמרת לכולם בטבלה
`country_trails` ל-30 יום, או עד שכללי הדירוג משתנים. בלי הטבלה זה עובד, אבל
נבנה מחדש בכל שרת.

## אזורי טיול

בתוך מדינה ב"מסלולים בעולם", מתחת לשם שלה, כפתור **"אזורי הטיול ב…"** (רק
במדינה שנכתבה לה סקירה). הוא פותח תצוגה נפרדת: פסקת פתיחה, ואז 5–10 האזורים
העיקריים להליכה — לכל אזור פסקה (אופי ההליכה, עונה, לינה, עומס, למי מתאים) ומיד
אחריה הטרקים והמסלולים המוכרים בו, עם אורך, ימים, קושי ומגבלות — ופסקת סיכום. בסוף
כל פסקה ותיאור טרק הקישורים לדפים שמהם נלקח המידע, ולמטה רשימת כל המקורות.

**על המפה.** לכל אזור כפתור "הצג על המפה": המפה עוברת לאזור ומסמנת אותו בקו
מקווקו, עם המקומות שמגדירים אותו (נקודות לבנות) ונקודות ההתחלה של הטרקים (צהובות).
"כולם על המפה" מציג את כל האזורים ממוספרים כמו בטקסט. בטלפון החלונית מתקפלת כדי
שהמפה תיראה, ובשורה מתחת לכותרת שלה אפשר לעבור לאזור הקודם או הבא ולחזור לקריאה
(באותו מקום שבו עצרת).

איך האזור מסומן: "הדולומיטים" או "צ'ינקווה טרה" אינם מחוז, ולכן קו של מחוז היה
מטעה. המודל נותן לכל אזור 4–8 מקומות שפרושים עד קצותיו (עיירות, פסגות, אגמים),
הם מאותרים ב-OpenStreetMap (Nominatim), ומסביבם נמתח קו עם שוליים של כ-8 ק"מ.
מקום שרחוק מאוד מכל השאר (כפר באותו שם במחוז אחר) מושמט. אזור שהוא בדיוק מחוז
אחד או כמה (אי, ואל ד'אוסטה) מסומן בקווי המחוזות עצמם מקובץ האזורים.

**"פתח מסלול" והקו על המפה.** כל טרק בסקירה מחופש בשמו ב-Waymarked Trails —
אותו מקור של מסלולי העולם באפליקציה (OpenStreetMap). מסלול נלקח רק אם השם שלו
מכיל את רוב המילים של הטרק ואת אותם מספרים (Alta Via 1 אינו Alta Via 2), ורק אם
הוא באזור. אז הטרק מקבל כפתור "פתח מסלול" שפותח את הכרטיס שלו (ו"חזרה לרשימה"
מחזירה לסקירה, לאותו מקום), והקו שלו, מפושט, נשמר בקובץ ומצויר בכתום כשהאזור מוצג
על המפה. טרק שאין לו מסלול מסומן ב-OSM (רוב מסלולי היום, הקפת Tre Cime) נשאר
בלי כפתור. זה קורה בזמן הכתיבה; לסקירות שכבר נכתבו:
`node scripts/writeCountryGuide.mjs --link` (חינם, בלי מודל).

**איך זה נכתב.** פעם אחת לכל מדינה, מראש, על ידי המנהל — אף פעם לא כשמשתמש פותח.
הסקירה נשמרת כקובץ `public/country-guides/<קוד>.json` (והרשימה ב-`index.json`
שם), ועולה לאוויר עם ה-deploy הבא. כדי לא לשלם לפי קריאה, הכתיבה רצה דרך המנויים:
Claude Code (‏`claude -p`, מודל Sonnet) ו-Codex (‏`codex exec`, מודל gpt-5.6-terra),
שניהם עם חיפוש ברשת:

```bash
node scripts/writeCountryGuide.mjs IT                      # מדינה אחת, דרך Claude
node scripts/writeCountryGuide.mjs --queue                 # כל מה שעוד לא נכתב, לפי הסדר
node scripts/writeCountryGuide.mjs --queue --via codex     # במקביל, דרך Codex
```

ל-Codex צריך גרסה עדכנית של כלי שורת הפקודה (זו שבתוך אפליקציית Codex ישנה מדי
ל-gpt-5.6-terra); היא מותקנת ב-`~/.local/share/codex-cli` עם
`npm install --prefix ~/.local/share/codex-cli @openai/codex@latest`.

שתי ריצות `--queue` עובדות זו לצד זו בלי לכתוב אותה מדינה פעמיים. הסדר הוא של
`scripts/countryGroups.mjs`: אירופה, דרום ומרכז אמריקה, אסיה, ארה"ב וקנדה, אפריקה,
אוסטרליה וניו זילנד. כשמכסת המנוי נגמרת הריצה נעצרת; מריצים שוב אחרי שהמכסה
מתחדשת והיא ממשיכה מאיפה שעצרה. יומן הריצות ב-`docs/country-guides/runs.log`.
אפשר גם דרך ה-API בתשלום (`--via api --model claude-opus-5-5`), כ-0.5–1 דולר למדינה.

מודלים נוטים לסמן אזור כמחוז שלם גם כשהוא פינה ממנו ("אנדרוס" כל דרום הים
האגאי) — אז כשהמקומות של האזור ממלאים פחות משליש מהמחוזות, הקו נמתח סביב
המקומות. אחרי שינוי בכלל הזה (או בניקוי הטקסט) מריצים
`node scripts/writeCountryGuide.mjs --reshape`, בלי לשאול מודל שוב.

**בדיקת המקורות.** מקור נשאר רק אם הוא דף שהחיפוש באמת החזיר (ב-Codex, שלא מוסר
את רשימת הדפים: דף שקיים), ורק אם הדף מזכיר את הטרק או האזור שהוא מצוטט עבורו —
מודל נוטה לצטט דף על מסלול אחד בשביל מסלול אחר. פסקה שכל המקורות שלה נפלו נשארת
בלי קישור.

## הרים, יער ונהרות

ב"מסלולים בעולם", ליד כל מדינה, וליד כל אזור אחרי שבוחרים מדינה, יש שורה אחת:
⛰ הרים · 🌲 יער. הנחלים מופיעים רק ליד מסלול (🌊) — כמעט בכל מדינה ואזור יש
נחלים זורמים איפשהו, אז שם המילים לא אמרו כלום ותפסו שורה בטלפון. בראש הרשימה של
מדינה (או אזור) מופיעים גם הרכסים העיקריים שלה. מעל כל רשימה יש שורה קבועה של שני
תפריטים: **"סינון"** (נוף, ובמדינה שנאספו לה נתונים גם מטיילים ורמת קושי) ו**"סדר"**.
הנוף בתוך "סינון" הוא שלוש כותרות — הרים, יער, נהרות ונחלים — וכל אחת נפתחת בלחיצה
עם הסבר קצר והאפשרויות: הררי / דרמטי / דרמטי מאוד;
מיוער (רבע מהשטח) / מיוער מאוד (חצי); נחלים שזורמים כל השנה / גם עונתיים. סוג
היער (מחטני, נשיר, מעורב…) הוא מידע בשורה של כל מדינה, לא מסנן. **סדר** (תפריט אחד
יחד עם הסדר לפי מטיילים):
מהגבוה לנמוך לפי האחוז ההררי, הדרמטי, הדרמטי מאוד, המיוער או עם נחלים זורמים, או
"כל הנופים יחד" — ציון שבו ההרים שווים חצי, היער 30% והנחלים 20% (`sortValue`).
ליד כל שורה מופיע המספר שלפיו היא מסודרת.

- **הרים — דרמטיות ולא גובה.** לכל תא של כקילומטר נמדד ההפרש בין הנקודה הגבוהה
  לנמוכה ברדיוס של כ-2.5 ק״מ: כמה הקרקע יורדת סביבך. רמה גבוהה ושטוחה (טיבט,
  האלטיפלנו) יוצאת מתונה או שטוחה, והדולומיטים דרמטיים מאוד. הדרגות: שטוח (פחות
  מ-150 מ׳), גבעות (150), הרים מתונים (400 — הגליל, היער השחור), הררי (700 —
  הווז׳), הרים דרמטיים (1,000 — גלנקו, הטטרה, יוסמיטי), דרמטיים מאוד (1,500 —
  צרמט, הדולומיטים, ערוץ ויקוס). המילה ליד מדינה היא הדרגה הגבוהה שמכסה לפחות
  **עשירית** מהשטח; האחוז אומר כמה. המקור: GMTED2010 (נחלת הכלל).
- **יער וסוגו.** מפת הכיסוי של Copernicus ל-2019 (100 מ׳, CC BY 4.0): כל פיקסל
  הוא יער סגור או פתוח, מאחד הסוגים. "מיוער" = לפחות רבע מהשטח; סוג נקרא בשמו
  כשהוא לפחות רבע מהיער. מיני עצים מדויקים (אשור, אשוח) אין במפה — רק הסוג.
- **נהרות ונחלים.** מודל עולמי (Messager ואחרים, Nature 2021, CC BY 4.0) שמעריך
  לכל קטע נהר עם אגן של 10 קמ״ר ומעלה אם הוא מפסיק לזרום יום בשנה, או חודש.
  **כל השנה** = לא מפסיק (או נהר של ממש, 5 מ״ק בשנייה ומעלה בחודש היבש). **עונתי** =
  מפסיק, אבל לפחות חלק מהשנה זורם: יבש פחות מחודש, או יבש יותר אבל לא במדבר.
  ואדי מדברי שזורם ימים בודדים לא נספר. "הרבה / לא מעט / מעט" — לפי איזה חלק
  מהשטח נהר חוצה. **מגבלות:** נחלים קטנים מאוד (ליד פסגות) לא במודל; והמודל חלש
  במזרח התיכון — הירדן יוצא אצלו "עונתי", ולכן מעל 5 מ״ק בשנייה נחשב תמיד זורם.
  במסלולים בישראל ממשיכים לסמוך על הרשימה הידנית (`perennialStreams.ts`).
- **רכסים** — GMBA Mountain Inventory v2 (CC BY 4.0), בשמות העבריים של ויקינתונים
  כשיש.
- **לכל מסלול.** במדינות שנאספו, גם לכל מסלול ברשימה יש את השורה, והסינון והסדר
  חלים על המסלולים (באחוזים מהדרך: "דרמטי 100% מהדרך"). בכרטיס המסלול יש שורה
  **"נוף ושטח"**: כמה דרמטיים ההרים סביב הדרך ובאיזה רכס, היער וסוגו, וכמה מהדרך
  עוברת בטווח של כקילומטר מנחל שזורם כל השנה או עונתי. נקודה כל 200 מ׳ לאורך
  המסלול קוראת את התא שלה. נאסף ב-`scripts/collectLandscape.mjs` על המק (הוא קורא את
  שכבות הקילומטר מהמטמון) לקובץ `src/data/trail-landscape.json.gz` — commit ו-deploy.
  נאספו (2026-10-04, 93 מדינות, כ-15,400 מסלולים) לפי סדר העדיפויות: אירופה, דרום ומרכז אמריקה, אסיה, ארה״ב
  וקנדה, אפריקה, ואוסטרליה וניו זילנד (הרשימה המלאה: `GROUPS` בסקריפט). לא נאספו:
  רוסיה, בלארוס ואוקראינה, מדינות ערב, ומדינות מוסלמיות שישראלים לא מטיילים בהן
  בחופשיות (איראן, טורקיה, אינדונזיה, מלזיה, מרכז אסיה). אלבניה, בוסניה וקוסובו כן.
  להריץ שוב (חינם, כ-15 שניות למדינה; המדינות שכבר נאספו נאספות מחדש, אלא אם מוסיפים
  `--skip-done`):
  `node scripts/collectLandscape.mjs --build --europe` — או `--latam`, `--asia`,
  `--north-america`, `--africa`, `--oceania`, או `--world` לכולן; או קודי מדינות
  (`--build CH AT`). `--build` בונה את רשימת המדינה כשאין או כשהשמורה חלקית, עם
  זמן ארוך יותר מזה של האפליקציה; `--rebuild` בונה אותה מחדש בכל מקרה.
  רשימה של מדינה נבנית מחדש מעצמה אחרי 30 יום, ומסלולים חדשים בה בלי נוף עד
  האיסוף הבא — כדאי להריץ `--world --build` פעם בחודש-חודשיים.
  מסלול בלי נתונים מסומן "אין מידע על המסלול הזה". **מגבלה:** מטעים (בעיקר זיתים,
  למשל בקורפו) נספרים לפעמים כיער.
- **איך זה בנוי.** `scripts/buildLandscape.mjs` מוריד פעם אחת כ-3.7GB לתיקייה
  `~/.cache/navi-landscape`, מחשב את כל העולם בתאים של כקילומטר, ושומר רק סיכומים
  לכל מדינה ואזור ב-`src/data/landscape.json.gz` (כמה מאות KB). אין קריאה לשום
  שירות בזמן אמת ואין עלות. הספים שהופכים את המספרים למילים נמצאים רק ב-
  `src/lib/landscape.ts`, ואפשר לשנות אותם בלי לבנות מחדש; אחרי שינוי מריצים
  `node scripts/checkLandscape.mjs`. השכבות של קילומטר נשארות בתיקיית המטמון —
  בשביל שלב הבא: אותו מידע לכל מסלול.

## רמת קושי

שלוש רמות — **קל**, **בינוני**, **קשה** — שנקבעות רק ב-`src/lib/difficulty.ts`, כך
שהרשימה והכרטיס לעולם לא אומרים דברים שונים. שני מקורות, ולא מערבבים ביניהם:

1. **הדירוג של Komoot** — במסלולי עולם ש-Komoot מכיר (אותם דפי "הטיולים הטובים
   ביותר" של "מה אומרים מטיילים"). Komoot מדרג כל מסלול לפי הכושר שהוא דורש ולפי
   השטח יחד (קל / בינוני / קשה), ולכן הוא עדיף: אורך ועליות לא רואים טיפוס על סלעים
   או שביל חשוף. נשמר רק כשהמסלול ב-Komoot מכסה לפחות חצי מהמסלול שלנו — לולאה של
   שעתיים בקצה של שביל באורך 40 ק"מ לא אומרת כלום על השביל (`GRADE_MIN_COVER`
   ב-`src/lib/trailCrowd/match.ts`).
2. **לפי האורך והעליות** — כל 100 מ' עלייה נחשבים כמו קילומטר הליכה במישור: עד 10
   ק"מ כאלה קל, עד 18 בינוני, יותר מזה קשה. אותה נוסחה של זמן ההליכה המשוער
   (`src/lib/hikeEffort.ts`). כך יש רמה לכל 83 המסלולים בישראל (נכתבת ל-
   `public/trails.json` ב-`node scripts/buildDifficultyIndex.mjs`, אחרי
   `generateTrailIndex.js`), וכל מסלול שנפתח על המפה, כש-Komoot לא מדרג אותו.
   מסלול של כמה ימים נחשב "קשה" כמכלול.

**איפה רואים.** בכל שורה ברשימת המסלולים בישראל (עם האורך והעלייה), ברשימת המדינה
ב"מסלולים בעולם", ב"המסלולים המובילים" וב"לפי דירוג"; בכרטיס המסלול ליד זמן ההליכה
(עם המקור), ובכרטיס של מסלול עולם לפני הטעינה. **סינון** — בישראל תפריט "רמת קושי"
בשורת המסננים; בעולם חלק "רמת קושי" בתפריט "סינון", בכל מדינה שנאספו לה נתוני
מטיילים, וב"לפי דירוג". אפשר לבחור כמה רמות. רוב מסלולי העולם בלי רמה (Komoot מדרג רק את
המובילים של כל אזור), ולכן מסלול בלי רמה **לא** מוצג כשמסננים, אלא אם מסמנים "להשאיר
מסלולים בלי רמת קושי". מסלול עולם בלי דירוג של Komoot מקבל רמה כשפותחים אותו —
לפי האורך והעליות.

**מילוי למדינות שכבר נאספו.** רמת הקושי נשמרת יחד עם מספרי Komoot בטבלה
`trail_crowd` (בתוך העמודה `sources`, בלי שינוי בטבלה). איסוף חדש של מדינה שומר אותה
מעצמו. למדינות שנאספו לפני כן: `node scripts/fillKomootGrades.mjs` (או עם קודי מדינות,
ו-`--dry` לבדיקה בלי לכתוב) — קורא שוב את אותם דפי Komoot, ישירות ובחינם, בלי
חיפוש ובלי קרדיטים של Tavily.

## מה אומרים מטיילים

שני מדדים למסלולי עולם, כדי לעזור לבחור מסלול לפי מה שמטיילים אחרים עשו ואהבו:

- **כמות מטיילים** — "הרבה מאוד", "הרבה", "כמות ממוצעת", "מעט", "מעט מאוד", **ביחס
  לשאר המסלולים באותה מדינה שיש עליהם מידע** ולא במספר מוחלט: 10% העליונים "הרבה
  מאוד", 20% הבאים "הרבה", 40% באמצע "ממוצע", 20% "מעט" ו-10% התחתונים "מעט מאוד".
- **ציון** — ציון המטיילים ב-Komoot, על סולם של 5, עם מספר הדירוגים.

**מאיפה המספרים.** הפופולריות של מסלולים מאוד לא אחידה: מעט מסלולים מקבלים את רוב
המטיילים, ולרוב המסלולים המקומיים אין שום תיעוד. לכן לא מחפשים כל מסלול לחוד, אלא
מתחילים מהרשימות שאתרי המסלולים עצמם כבר מדרגים:

1. **Komoot** — לכל אזור יש ב-Komoot דף "הטיולים הטובים ביותר" עם 10 המסלולים
   המובילים, כל אחד עם מספר המטיילים, הציון ומספר הדירוגים, והקו שלו על המפה.
   הדפים נמצאים בחיפוש Tavily (כ-2 חיפושים לכל אזור במדינה, ועוד 2 למדינה כולה),
   ונקראים ישירות מ-Komoot, דף אחרי דף, כמו בדפדפן.
2. **התאמה לפי מיקום, בלי מודל שפה** — מסלול של Komoot שייך למסלול שלנו כשלפחות 60%
   מהנקודות שלו במרחק של עד 150 מ' מהשביל. כשהוא עובר על כמה שבילים — הוא שייך לקצר
   שבהם. שביל ארוך פי 5 ויותר מהמסלול לא מקבל את המספרים שלו, כדי שטיול יום מפורסם
   על ה-E4 לא יהפוך את כל ה-E4 ל"הרבה מאוד" (משביל רב-יומי כמו Menalon, מקטע של יום
   כן נספר). לכל שביל נלקח המסלול הכי מוטייל שעליו.
   **מסלול שלא עובר על אף שביל ברשימה** — או רק על שביל ארוך פי 2 ויותר ממנו (מסלול
   ערוץ הקארס על "Anillo de Picos" הרב-יומי) — מוביל לשביל שמתחתיו: שני ריבועים
   זעירים (כקילומטר) לאורכו, כל השבילים שעוברים שם, ומי שהמסלול הולך עליו לפי אותם
   כללים נוסף לרשימת המדינה. כך נכנסו לספרד Caminito del Rey, Cala Bóquer ו-Caldera
   Blanca. חינם (Waymarked בלבד), כשלוש בקשות למסלול.
3. **ויקיפדיה** — כמה פעמים נקראו הערכים של המסלול, בכל השפות, ב-24 החודשים
   האחרונים. נבדק רק לשבילים הארוכים והאזוריים ולמה שנמצא ב-Komoot. חינם. מכאן
   מקבלים רמת תנועה שבילים ארוכים מפורסמים (E4, E6) ש-Komoot לא מדרג כשלם.

כמות המטיילים היא הגבוה מבין שני המדדים: המיקום של מספר המטיילים ב-Komoot בין

מטיילים (ברירת המחדל), לפי ציון או טיולי יום קודם — בתפריט "סדר" שלידו. **בכרטיס המסלול** שורה "מה אומרים מטיילים" עם המסלול ב-Komoot
שהמספרים ממנו וקישור לדף שלו, ותאריך האיסוף. מדינה שלא נאספה נראית בדיוק כמו קודם.

**המסלולים המובילים** של מדינה — 10 טיולי היום ו-3 השבילים הארוכים עם הכי הרבה
מטיילים (לפי אותו דירוג, הציון שובר שוויון). טיולי יום ושבילים ארוכים בנפרד: את
הראשונים מדרג Komoot, את השניים בעיקר ויקיפדיה, ואי אפשר להשוות ביניהם. נכנס לרשימה
רק מסלול שספרו בו מטיילים (Komoot): שביל ארוך שידוע רק מוויקיפדיה עלול להיות מפורסם
בגלל משהו אחר — ביוון, מסלול "המרתון הקלאסי" קיבל את הקריאות של ערך המרוץ. הם
מוצגים בשלושה מקומות, תמיד אותה רשימה (`leadersOf`):
- **בראש רשימת המדינה** — שורה נפתחת "המסלולים המובילים", ואחרי בחירת אזור "המובילים
  ב{אזור}". לא מסוננת לפי החודש (מסלול מפורסם נשאר מפורסם בינואר), אבל ליד כל שם
  נקודת הצבע של החודש שנבחר.
- **ברשימת המדינות** — מתחת למדינה שנאספה, שמות שלושת המובילים שלה.
- **על המפה** — כשהשכבה "מסלולים בעולם" פתוחה: נקודה זהובה במרכז כל מסלול מוביל
  (מזום 5), ומזום 7.5 גם השם, רמת התנועה והציון. לחיצה פותחת את הכרטיס.
`/api/world-trails/leaders` מחזיר את המובילים של כל המדינות שנאספו (נשמר ב-CDN ל-10 דקות).

**דירוג מסלולים בעולם** ("מסלולים בעולם" → "לפי דירוג"): כל המסלולים שיש עליהם
נתונים מ-Komoot, מכל המדינות שנאספו, ברשימה אחת לפי **ציון משוקלל** (0–100) — כדי
לראות מיד מהם המסלולים הפופולריים ביותר. רק Komoot: ויקיפדיה אומרת כמה שם מפורסם, לא
כמה הולכים בו, ורק כך מסלולים ממדינות שונות נמדדים באותו סרגל. הציון:
- **כמות מטיילים — 55%.** המדד הישיר לפופולריות, וזו המטרה.
- **מספר דירוגים — 20%.** בערך חמישית מהמטיילים מדרגים, כך שהוא חופף ברובו לכמות
  המטיילים, ומוסיף בעיקר כמה אפשר לסמוך על הציון.
- **הציון — 25%.** "מכווץ" לכיוון 4.6 (הממוצע הרגיל ב-Komoot) כאילו היו עוד 20
  דירוגים: 5.0 משני מדרגים שווה כ-4.64, ו-4.8 מ-500 נשאר 4.8. נספר מ-4.0 (0) עד 5.0
  (מלא), כי ב-Komoot כמעט הכל בין 4.3 ל-5. מתחת ל-5 דירוגים אין ציון, כמו בשאר
  האפליקציה ("אין מספיק מידע"), והמסלול נמדד בציון הממוצע.
- המטיילים והדירוגים **בסקאלה לוגריתמית** מול תקרה קבועה — 50,000 מטיילים, 5,000
  דירוגים: המעבר מ-100 ל-1,000 מטיילים שווה כמו מ-1,000 ל-10,000. התקרה קבועה (לא
  "המקסימום הנוכחי") כדי שהציון של מסלול לא ישתנה כשנאספת מדינה חדשה או לפי הסינון.

לדוגמה (2026-10): Caminito del Rey — 13,587 מטיילים, 4.9 מ-1,038 דירוגים — 87; מסלול
חציוני (128 מטיילים, 4.7 מ-26) — 49. ברשימה: מקום, ציון משוקלל, המספרים המלאים של
Komoot (לא "הרבה/מעט מטיילים", שהוא יחסי למדינה), המדינה, הנוף ופס 12 החודשים. מעל
הרשימה ארבעה תפריטים נפתחים: יבשת, מדינה (רק אלה שיש בהן מסלולים מדורגים), חודש (רק
מסלולים ב"עונה מומלצת" בו) וסדר — ציון משוקלל (ברירת המחדל), כמות מטיילים, מספר
דירוגים או ציון. מסלול שחוצה גבול מופיע פעם אחת, ומסלול Komoot אחד שהותאם לשני
מסלולים שלנו (שביל וקטע של שביל ארוך יותר) נשאר רק על הקצר מביניהם. הרשימה מגיעה
מ-`/api/world-trails/ranking` (נשמר ב-CDN ל-10 דקות), והכללים כולם ב-`score.ts`
(`komootOf`, `popularityScore`, `byRank`); `node scripts/checkCrowd.mjs` בודק אותם.

**שם שהוא רק סימון.** הרבה שבילים מסומנים קיימים ב-OpenStreetMap רק בשם הסימון שלהם —
"105", "GG-2", "RYF75" — וכך גם כמה מהמפורסמים ביותר: Tre Cime di Lavaredo הוא "105",
Preikestolen הוא "RYF75". כששם המסלול אין בו אף מילה (שלוש אותיות ומעלה, בלי ספרות,
ולא קיצור באותיות גדולות כמו PR או GR), השורה מוצגת בשם של המסלול ב-Komoot, ומתחתיו
"סימון בשטח: 105" — ברשימת "לפי דירוג", ברשימת המדינה, ב"המסלולים המובילים" ובתוויות
של הכוכבים על המפה (`trailTitle` ב-`score.ts`). בכרטיס המסלול עצמו השם לא משתנה; שורת
"מה אומרים מטיילים" בו כבר מראה את המסלול ב-Komoot.

**האיסוף ידני, מדינה אחרי מדינה**: מהגדרות → מתקדם → "מדדי מטיילים", או מהמחשב בלי
מגבלת זמן: `node scripts/collectCrowd.mjs GR` (צריך ב-`.env.local` את `TAVILY_API_KEY`,
`SUPABASE_SERVICE_ROLE_KEY` ו-`NEXT_PUBLIC_SUPABASE_URL`). איסוף שקרא מעט מדי מסלולים
(Komoot לא ענה) לא נשמר, כדי לא לדרוס נתונים טובים. נאספו עד כה (2026-10-07): יוון,
ספרד, מלטה, איטליה, פורטוגל, שווייץ, אוסטריה, צרפת, סלובניה, נורווגיה, בריטניה, גרמניה,
אירלנד, איסלנד, קרואטיה ומונטנגרו — לפי סדר העדיפויות ב-`scripts/countryGroups.mjs`;
כ-2 חיפושים לכל אזור במדינה, ובסך הכל כ-450 חיפושים ל-13 המדינות האחרונות, בתוך
המכסה החינמית. אחרי איסוף מריצים `collectLandscape.mjs` לאותן מדינות, כדי שגם
המסלולים שנוספו יקבלו נוף. הנתונים בטבלה `trail_crowd` ולא
מתעדכנים לבד.

**למה רק Komoot.** AllTrails ו-Wikiloc חוסמים קריאה של הדפים שלהם, ובתוצאות חיפוש
מופיע רק קטע מהרשימה, כמעט בלי מספרים. ל-Google Places יש ציונים, אבל התנאים שלו
אוסרים לשמור אותם — ובלי לשמור אי אפשר לסנן רשימה של מאות מסלולים. Tripadvisor
מדרג אטרקציות תיירותיות ולא שבילים. חיפוש נפרד לכל מסלול נוסה ונפסל: 600 חיפושים
למדינה, ולרוב המסלולים אין שום תיעוד.

## סידור המסך

כמה כללים שכל חלונית באפליקציה שומרת עליהם, כדי שהמסך בטלפון לא יתמלא:

- **חזרה אחורה**:
  - כרטיס של מסלול שנפתח מ"מסלולים בעולם" מקבל כפתור **"חזרה לרשימה"**, והרשימה
    נפתחת בדיוק כמו שנעזבה: המדינה, האזור, החודש, הסינון והמקום ברשימה.
  - סגירת מסלול שנטען מהרשימה מחזירה אליה.
  - אחרי סגירת מסלול מופיע מתחת לתיבת החיפוש **"חזרה ל{שם המסלול}"**, שמחזיר אותו
    בלחיצה, עד שנפתח מסלול אחר.
  - **כפתור "אחורה" של הטלפון** סוגר מסלול פתוח, או כרטיס של מסלול בעולם (וחוזר
    לרשימה אם הכרטיס נפתח ממנה), בלי "בטוח?" — שום דבר לא הולך לאיבוד.
- **תיבת חיפוש המקומות נשארת גם כשמסלול פתוח**: מקום שנבחר (כפר מ"על המסלול", הדרך
  להתחלה) מקבל סיכה, והמסלול נשאר כמו שהיה.
- **אפשר לסמן ולהעתיק טקסט** בחלוניות ובכרטיסים (למשל שם מקום, כדי לחפש אותו). רק
  המפה וכפתורי הצד לא, כי שם לחיצה ארוכה היא תנועה על המפה.
- **תלת מימד**: המפה נפתחת מוטה, כך שהתלת מימד נראה מיד. כשהוא כבוי, מסלול חדש לא
  מטה אותה, והחלפת סוג מפה לא מחזירה אותו.

- **לחיצה מחוץ לחלונית סוגרת או מצמצמת אותה** — חיפוש המסלולים, כרטיס המסלול,
  הנסיעה בכביש, כרטיס מסלול בעולם, תפריט "תצוגת מפה", טקסט הקריינות, וחלונות
  ההגדרות והאזור האישי.
- **חלונית פתוחה מכסה את כפתורי הצד** במקום שהכפתורים יעלו עליה; לחיצה על המפה
  מצמצמת אותה והכפתורים חוזרים. רשימת המסלולים פתוחה בטלפון תופסת את כל גובה המסך
  עד כפתור הצ׳אט (מכסה גם את תיבת החיפוש), כדי שלתוצאות יהיה מקום.
- **מסננים בשורה אחת של תפריטים נפתחים** מעל הרשימה, קבועה ולא חלק מהגלילה
  (`FilterDropdown`): מה שבוחרים נפתח בתיבה מעל הרשימה ונסגר בלחיצה מחוץ לה.
- **בתחתית המסך** — כפתור הסיור, המדריכה, פס ההתקדמות וכרטיס המסלול נמדדים
  ונערמים זה מעל זה, כך שגם כשהמדריכה מדברת שום דבר לא מוסתר.
- **"הסתר הכל"** מעלים גם את חלונית החיפוש ואת תכנון הנסיעה, ומחזיר אותם בדיוק
  כמו שהיו.
- **מעט טקסט בפתיחה**: נושאים ארוכים (מדריכים ומידע נוסף, התראת סטייה, מזג
  אוויר, מים לרחצה וצל) מוצגים כשורה אחת עם תקציר, ונפתחים בלחיצה.
- **כפתורי הצד** צמודים לקצה השמאלי של המסך.
- **שורה שנפתחת בתוך כרטיס** (מזג אוויר, מים לרחצה וצל) מצוירת כמו כפתור:
  מסגרת, התקציר מתחת לכותרת, וכפתור כחול "פרטים".
- **המסלול שנבחר בולט**: כשמסלול פתוח, או כשלוחצים על מסלול בשכבת "מסלולים
  בעולם", כל שאר המסלולים בשכבה הופכים לאפורים וחלשים, והמסלול שנבחר מצויר
  בכתום עם שוליים כהים.

## מה מופיע רק במסלולים בישראל

"מים לרחצה וצל בקיץ" והתזכורת "לפני שיוצאים — לאמת ברט״ג" מופיעים רק במסלול
שרובו בישראל (כולל יהודה ושומרון והגולן), ובמסלול בחו״ל לא נשלחת בכלל בקשה על
מים. הסיבה: מפת הצל מכסה רק את ישראל, והכללים מה נחשב מים בטוחים לרחצה נבנו לפי
נחלים ובריכות בארץ. הבדיקה נעשית במכשיר לפי גבולות המדינות (`src/lib/inIsrael.ts`),
בלי שירות חיצוני ובלי עלות.

התזכורת לרט״ג מופיעה בכל מסלול בישראל ולא רק בשטחים של רשות הטבע והגנים: אין
מקור אמין שאומר אם מסלול עובר בשטח שלהם (במפות הפתוחות הסימון הזה חסר ולא
עקבי), ומה שהיא מזכירה לבדוק — חום, שיטפונות, סגירת מסלולים ואיכות המים — נוגע
לכל טיול בארץ.

## מסלולים בעולם

שכבת מסלולים מסומנים מכל העולם מ-[Waymarked Trails](https://hiking.waymarkedtrails.org).
מסלול ששמו בכתב שאינו לטיני מקבל שם באנגלית — מתגיות OSM כשיש, ואחרת בתרגום של
מודל שפה — ונשמר בטבלה `trail_name_en`, שמשמשת גם לחיפוש לפי השם האנגלי. המדינה
של כל מסלול מחושבת פעם אחת ונשמרת בטבלה `trail_country`.

### צבעי הקווים

הקווים מצוירים על ידי Waymarked Trails (אריחי תמונה), לא על ידי האפליקציה. הצבע
מראה את **דרגת השביל**, לא את הסימון שלו בשטח: סגול — מקומי, כחול — ארצי, כתום —
אזורי, אדום — בינלאומי. המקרא מופיע בתפריט השכבות (שבו בוחרים סוג מפה), מתחת
ל"מקרא", כל עוד השכבה "מסלולים בעולם" דולקת (`MapLegend` ב-`Controls.tsx`).
ההתאמה בין צבע לדרגה באה מהתצפית של הבעלים; לא אימתנו אותה מול התיעוד של
Waymarked Trails. כשפותחים מסלול, שאר הקווים הופכים לאפורים והמסלול הנבחר כתום.

### שם באותיות לטיניות

כל מסלול ששמו בקירילית (בולגרית, רוסית, אוקראינית, סרבית, מקדונית…), ביוונית,
בגאורגית או בארמנית מוצג גם באותיות לטיניות, מתחת לשם המקורי — ברשימות של
"מסלולים בעולם", בדירוג, ב"מסלולים המובילים", בחיפוש, בכרטיס המסלול, במקטעים
ובשמות הכוכבים על המפה. השם המקורי נשאר תמיד.

- **קודם השם באנגלית** (מ-OSM או מהתרגום ב-`trail_name_en`), כשיש כזה — הוא גם
  מתרגם מילים ("Musala Trail").
- **אחרת תעתיק לפי כללים** (`src/lib/romanize.ts`): אות אחר אות, בשיטה הרשמית של
  כל שפה — בבולגריה החוק של 2009 ("войвода - х.Марица" → "voyvoda - h.Maritsa"),
  ביוון ELOT 743, בגאורגיה השיטה הלאומית, בסרביה האלפבית הלטיני שלה (š, č, đ).
  חינם, מיידי, בלי שרת. המדינה של הרשימה בוחרת את שיטת הקירילית; בלעדיה —
  האותיות שרק שפה אחת משתמשת בהן. תעתיק לא מתרגם: "х." (בקתה) נשאר "h.".
- כתבים שלא נכתבים אות אחר אות (סינית, יפנית, ערבית, תאית) לא מקבלים תעתיק,
  ונשארים עם התרגום כמו קודם.

אחרי שינוי בטבלאות: `node scripts/checkRomanize.mjs`.

### מקטעי המסלול

מסלול ארוך ב-OSM ממופה לפעמים כ"מסלול־על" שמורכב מכמה מסלולים — מקטע לכל
יום הליכה. אצל מסלול כזה מופיעה בכרטיס שורה נפתחת **"מקטעי המסלול"**, עם המקטעים
לפי סדר ההליכה: שם (ושם באותיות לטיניות כשהשם ביוונית וכד'), אורך, עלייה וירידה.

- **בכרטיס של מסלול שנבחר על המפה או בחיפוש** — לחיצה על מקטע פותחת את המקטע
  באותו כרטיס, מצויר על המפה, ואפשר לטעון רק אותו.
- **בכרטיס של מסלול שכבר נטען** — לחיצה על מקטע טוענת אותו במקום המסלול כולו.
- **במקטע** (בשני הכרטיסים, וגם בכרטיס המכווץ) יש כפתור **"חזרה למסלול הראשי"**,
  ומתחתיו "מקטע 5 מתוך 13" עם כפתורי **"המקטע הקודם"** ו**"המקטע הבא"**.
  מקטע שנלחץ ישירות על המפה מזהה לבד לאיזה מסלול ארוך הוא שייך.
- **מסלול עטיפה:** יש מסלולים ארוכים שממופים כמסלול אחד שעוטף את המקטעים
  האמיתיים (GR12 NL מכיל רק את "Floris V-pad - Hoofdroute", ובו 13 המקטעים).
  רמה עם מקטע יחיד נפתחת אוטומטית לרמה שמתחתיה.

הרשימה מחושבת מהנתונים של Waymarked Trails (`subroutes` ו-`superroutes`), בלי
עלות. השם הלטיני של מקטע הוא נקודות ההתחלה והסיום שלו מ-OSM; רק כשאין כאלה הוא
מתורגם, כמו שמות מסלולי העולם (ונשמר באותה טבלה). למסלול שכבר נטען השרת מחזיר
גרסה קצרה של הרשימה: `/api/world-trails?id=…&stages=1` (עם `&climb=0` בלי עלייה
וירידה — מספיק לכפתורי הקודם/הבא, וחוסך את הגבהים של מסלול־העל כולו).

## כלי המנהל

מי שמתחבר עם כתובת שמופיעה ב-`ADMIN_EMAILS` רואה בהגדרות סעיפים נוספים.
השרת הוא שמחליט מי מנהל, והכלים עצמם חסומים לכל השאר, לא רק מוסתרים.

- **מתקדם** — ספק ה-AI של המדריכה, בחירת הקול וכוונון שלו, בדיקת ניקוד, בדיקה בלי קליטה,
  ואיסוף "מה אומרים מטיילים" למדינה.
- **שימוש ועלויות AI** — הכל על השימוש ב-AI, בארבעה חלקים: המפתחות בתשלום (ההוצאה
  היום מול התקרה, הסרת התקרה ליום אחד, המגבלות וההתראות), השירותים החינמיים (הקרדיטים
  של ElevenLabs ושל Tavily), ופירוט השימוש לפי שימוש, מודל ומשתמש. הפירוט המלא בפרק
  "שימוש ב-AI". בראש הסעיף שורה על הגבלת הקצב לדקה: "משותפת לכל השרתים (Upstash)",
  או אזהרה כתומה כשהיא נספרת לכל שרת בנפרד (ראה "Upstash").
- **התראה על קרדיטים** — כשהקרדיטים של ElevenLabs או של Tavily עומדים להיגמר (90%, או
  צפי שייגמרו לפני החידוש) וכשהם נגמרו, מופיעה התראה על מסך המפה — רק למנהל.
- **שאלות ל"שאלו את Navi"** — 200 השאלות האחרונות שנשאלו בצ׳אט, עם התשובה. שאלה
  שהצ׳אט לא ידע לענות עליה ("אני לא בטוח", עומס) מסומנת בכתום, ואפשר להציג רק
  אותן — שם חסר הסבר ב-`src/components/help/features.ts`.

המנהל הם מסומנים "בתשלום" בצהוב, והחינמיים "חינמי" בירוק.

כמעט כל תוצר נשמר ומשמש את כולם, ולכן משלמים פעם אחת לכל נקודה או מסלול. הספק
החינמי ראשון בתור, כך שהמפתחות בתשלום נוגעים רק כשהחינמי לא זמין.

**על הרשומות של `gpt-5.6-sol` ו-`gpt-5.6-terra`.** הן שתי ריצות אמיתיות דרך ה-API, ב-6.10
בסביבות 16:50, מהסקריפט של "אזורי טיול" עם `--via api` (השוואת מודלים לפני שעברנו
ל-Codex). הסקריפט רץ על המחשב, ולכן השתמש במפתח שב-`.env.local` — לא במפתח של Vercel.
עלות משוערת: כ-$1.46.

| לאורח ביום, במפתחות בתשלום | $0.05 |

| תווי הקראה ב-ElevenLabs ביום | 3,000 למשתמש, 1,000 לאורח |
| חיפושים ב-Tavily ביום | 20 למשתמש, 5 לאורח |

**מה קורה במגבלה.** בתשלום — האדם (או כולם, בתקרה הכללית) ממשיך רק עם השירותים
החינמיים עד חצות: הטקסט נכתב ב-Gemini החינמי, ורק אם גם הוא לא זמין מופיעה הודעה
לנסות מחר. בהקראה — הטקסט מוקרא בקול של הטלפון, והורדה לשטח נעצרת עם "מגבלה יומית".
בחיפוש — "על המסלול" נכתב מהמקורות האחרים.

**הסרת התקרה ליום אחד.** בכלי המנהל, "הסר את התקרה להיום בלבד" מבטל את התקרה של כל
האפליקציה עד חצות; למחרת היא חוזרת לבד. המגבלה של כל אדם נשארת.

**בלי בסיס הנתונים אין מפתחות בתשלום.** אם אי אפשר לקרוא מה הוצא היום (Supabase לא זמין,
או ש-`schema.sql` עוד לא הורץ) המפתחות בתשלום סגורים והחינמיים ממשיכים.

### התראות במייל — Resend

נשלח מייל כש:
- אדם אחד (לא אתה) הוציא באותו יום יותר מסף ההתראה במפתחות בתשלום (ברירת מחדל $0.10);
- אדם הגיע למגבלה האישית שלו במפתחות בתשלום;
- האפליקציה הגיעה ל-80% מהתקרה היומית, וכשהגיעה לתקרה.

כל התראה נשלחת פעם אחת ביום, ונרשמת בטבלה `ai_alerts` — גם כשאין מייל מוגדר, היא
מופיעה בכלי המנהל תחת "התראות אחרונות".

**הגדרה, שלב אחר שלב:**
1. היכנס ל-[resend.com](https://resend.com) ← **Sign up**, **עם הכתובת שאליה יגיעו ההתראות**.
   בלי דומיין משלך, Resend שולח רק לכתובת שאיתה נפתח החשבון.
2. בתפריט: **API Keys** ← **Create API Key**. שם: `navi-alerts`, הרשאה: **Sending access**.
   העתק את המפתח — הוא מוצג פעם אחת בלבד.
3. ב-Vercel ← הפרויקט ← **Settings** ← **Environment Variables**, הוסף:
   - `RESEND_API_KEY` = המפתח מהשלב הקודם
   - `ALERT_EMAIL` = הכתובת שאליה יגיעו ההתראות

   סמן את שלוש הסביבות ולחץ **Save**.
4. **Deployments** ← הפריסה האחרונה ← **⋯** ← **Redeploy**.
5. באפליקציה: הגדרות ← שימוש ועלויות AI ← מגבלות שימוש והתראות ← **שלח מייל בדיקה**.
   בפעם הראשונה כדאי לבדוק גם בתיקיית הספאם, ולסמן "לא ספאם".

### Upstash — הגבלת קצב משותפת לכל השרתים

מעבר למגבלות היומיות, לכל נתיב יש גם הגבלת קצב לדקה (למשל 6 בקשות בדקה ל"על המסלול").
Vercel מריץ כמה שרתים במקביל, ובלי Upstash כל שרת סופר לחוד — מי שמציף את האתר מקבל
מכל שרת את המכסה מחדש. Upstash הוא שירות Redis שכל השרתים סופרים בו יחד. התוכנית
החינמית (500,000 פקודות בחודש) מספיקה בהרבה.

1. היכנס ל-[upstash.com](https://upstash.com) ← **Sign up** (אפשר עם Google).
2. ב-Console: **Redis** ← **Create Database**.
   - Name: `navi-ratelimit`
   - Primary Region: האזור הקרוב לשרתים של Vercel — אם לא שינית, **US East (N. Virginia), us-east-1**.
   - Plan: **Free**. לחץ **Create**.
3. בעמוד של ה-database, בחלק **REST API**, העתק את שני הערכים:
   `UPSTASH_REDIS_REST_URL` ו-`UPSTASH_REDIS_REST_TOKEN` (את הרגיל, לא את ה-read-only).
4. ב-Vercel ← הפרויקט ← **Settings** ← **Environment Variables**, הוסף את שניהם בדיוק בשמות
   האלה, בשלוש הסביבות, ו-**Save**.
   (לא דרך האינטגרציה של Upstash ב-Marketplace של Vercel: היא יוצרת משתנים בשמות אחרים,
   `KV_REST_API_URL` וכו', שהקוד לא קורא.)
5. **Deployments** ← הפריסה האחרונה ← **⋯** ← **Redeploy**.
6. בדיקה: הגדרות ← שימוש ועלויות AI. האזהרה הכתומה מתחלפת בשורה
   "הגבלת קצב: משותפת לכל השרתים (Upstash)".

### כשמוסיפים שימוש חדש ב-AI

כל קריאה לשירות AI עוברת `ensureAllowed` לפני ונרשמת ב-`recordAiUsage` אחרי, בתוך
`withAiUsage` של הנתיב — הכללים המלאים ב-`CLAUDE.md`. כך היא נספרת, מוגבלת ומופיעה
בכלי המנהל, ושורה חדשה נוספת לטבלה "איפה האפליקציה משתמשת ב-AI" שלמעלה.

**אחרי כל שינוי בקובץ צריך להריץ אותו שוב** — הוא לא רץ אוטומטית ב-deploy.

עמוד "שימוש ועלויות AI" מציג שגיאה של Supabase.

## הקלטת מסלול

כפתור "הקלטה" בסרגל הצד (מתחת ל"תכנון מסלול") מתחיל להקליט ומדליק את המיקום החי.
בזמן ההקלטה יש פס מתחת לחיפוש: זמן ומרחק, ובלחיצה — כל המספרים, "השהה" ו"סיים".
"סיים" פותח סיכום: שם (ברירת מחדל "הליכה · התאריך"), "שמור", "חזרה להקלטה" או מחיקה.

- **מה נמדד.** נקודה נשמרת רק כשהיא רחוקה 3 מ׳ לפחות מהקודמת ובדיוק של עד 35 מ׳, וקפיצה
  מהירה מדי של ה-GPS נזרקת — אחרת עמידה במקום הייתה מוסיפה מרחק. "זמן הליכה" הוא רק
  הזמן שבו זזים, "זמן כולל" כולל עצירות, וזמן ההשהיה נספר בנפרד. המרחק לא מחבר בין
  לפני השהיה לאחריה. כל המספרים מחושבים במקום אחד: `src/lib/recording/stats.ts`.
- **גובה.** בזמן ההליכה — הגובה של ה-GPS (רועש). בשמירה, כשיש קליטה, הגבהים מוחלפים
  בגבהים ממודל הגובה של Mapbox (אותו מודל של המפה התלת-ממדית), והעלייה והירידה מחושבות
  מהם. בלי קליטה זה קורה בסנכרון הבא.
- **איפה נשמר.** קודם כל במכשיר (IndexedDB), כך שזה עובד בלי קליטה ובלי התחברות.
  משתמש מחובר — ההקלטה עולה גם לחשבון (טבלה `recordings`), ומופיעה באזור האישי בכל
  מכשיר. הקלטה שנעשתה בלי קליטה או לפני ההתחברות עולה כשהחיבור חוזר. ההקלטה שבאמצע
  נשמרת במכשיר כל כמה נקודות: אם הטלפון סוגר את הדף, בפתיחה הבאה היא חוזרת מושהית.
- **שיתוף.** בלשונית "הקלטות": "קישור" (דורש התחברות) מסמן את ההקלטה כמשותפת ושולח
  `/?walk=<id>`, שפותח אותה ב-Navi אצל מי שמקבל. "בטל את השיתוף" מפסיק את הקישור.
  "קובץ GPX" עובד גם בלי התחברות ונפתח בכל אפליקציית ניווט. הקלטות לא משותפות לא
  נראות לאף אחד: אין להן גישה ציבורית בבסיס הנתונים, וקישור נקרא רק דרך השרת.

## התחברות

ההתחברות עם Google עוברת ב-PKCE (`src/lib/supabase.ts`): מי שמתחיל התחברות
שומר במכשיר סוד, וההתחברות נגמרת רק עם הסוד הזה. קישור שמכיל טוקנים לא מחבר

החזרה נשארו (האתר, ו-`app.navi.trails://auth-callback` לאפליקציה).

## Keeping Supabase awake

Supabase pauses free-tier projects after **7 days without activity**. When that
happens Google login, the personal area and the per-user guide quota all stop
working (the rest of the app keeps running — see `src/lib/personalArea.ts` for
how the UI degrades).

`vercel.json` registers a daily cron that calls `/api/keepalive`, which performs
one anonymous read against the database. That single request is enough to keep
the project counted as active.

- Set a `CRON_SECRET` env var in Vercel to lock the route down — Vercel Cron
  sends it automatically as `Authorization: Bearer $CRON_SECRET`. Without the
  var the route stays open.
- The route answers `503` when Supabase is unreachable, so a failed ping shows
  up in Vercel's logs instead of passing silently.
- Not on Vercel? Any daily scheduler works, e.g. a GitHub Actions job running
  `curl -fsS -H "Authorization: Bearer $CRON_SECRET" https://<your-app>/api/keepalive`.

Once a project is already paused, the cron can't revive it — unpause it from the
Supabase dashboard (possible for 90 days after the pause; the project ref, URL
and anon key stay the same, so no redeploy is needed).
